# Потоковый keep-alive

## 1. Какую задачу решает этот раздел

После того как поток начался, прокси может отправлять keep-alive с фиксированным интервалом, чтобы промежуточное устройство не закрыло простаивающее соединение.

## 2. Когда применимо и чего здесь нет

Этот ключ задаёт только интервал. Он не решает, отправлять ли до прихода первого токена, и не повторяет поток, который ещё не записал байт. Keep-alive пустой строкой для не потокового ответа — другой ключ.

## 3. Как настроить или вызвать

```yaml
requests:
  streaming:
    keepalive-seconds: 0
```

В примере конфигурации включённый интервал записан как 15. Нулевое значение, когда поле не записано, — это defaults в таблице.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| requests.streaming.keepalive-seconds | Интервал в секундах для сердцебиения SSE или Ping WebSocket. | Default is 0. | Меньше или равно 0 выключает. Тело сердцебиения SSE — `: keep-alive` плюс пустая строка. WebSocket отправляет управляющий кадр Ping. |

## 5. Типичные ошибки и границы

0 или отрицательное значение не отклоняется. Просто keep-alive не отправляется. Если задать только этот ключ положительным числом, сердцебиение до первого токена не отправляется.
