# Клиентские ключи

Здесь описаны только клиентские ключи закреплённого коммита, которыми вызывают публичные интерфейсы этого прокси. Это не ключи провайдеров upstream.

## 1. Какую задачу решает этот раздел

`access.api-keys` перечисляет клиентские ключи, которые принимает этот прокси. После настройки хотя бы одного действительного ключа публичные маршруты этого руководства проверяют ключ в запросе. Если список пуст, эти маршруты больше не требуют клиентский ключ.

## 2. Когда применимо и чего здесь нет

В конфигурации v8 это записывается в `access.api-keys`. Корневой список строк `api-keys` в старом файле по-прежнему загружается в то же поле. Если присутствуют оба, включая случай, когда новое поле явно записано пустым списком, берётся `access.api-keys`.

Если корневой `api-keys` — отображение, это группы провайдеров upstream. Он не считается клиентскими ключами и не может делить один ключ YAML со списком клиентов. Группы upstream, ключ управления и переменная окружения `MANAGEMENT_PASSWORD` на этой странице не описаны.

Пустые элементы удаляются. Повторы сохраняются один раз. Если ключей не осталось, встроенный поставщик `config-api-key` не регистрируется.

## 3. Как настроить или вызвать

```yaml
access:
  api-keys:
    - "YOUR_API_KEY"
```

При вызове маршрута этого руководства, которому нужен ключ, годится любая форма ниже. Берётся первый уже настроенный ключ в таком порядке: `Authorization`, `X-Goog-Api-Key`, `X-Api-Key`, параметр запроса `key`, параметр запроса `auth_token`.

Если `Authorization` начинается с `Bearer` и пробела, используется только следующий токен. Имя схемы не зависит от регистра. Иначе значение всего заголовка считается ключом.

```bash
curl https://example.invalid/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```bash
curl "https://example.invalid/v1/models?key=YOUR_API_KEY"
```

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| access.api-keys.value | Список клиентских ключей этого прокси. | nil | Пустые элементы удаляются, повторы игнорируются. Пустой список означает, что клиентские ключи не проверяются. |

## 5. Типичные ошибки и границы

Если не передан ни один из ключей выше, ответ — 401 с телом `{"error":"Missing API key"}`. Если значение передано, но ни одно не совпадает с конфигурацией, ответ — 401 с телом `{"error":"Invalid API key"}`.

На маршрутах реального времени, которые используют промежуточный слой аутентификации реального времени, та же неудача упаковывается в объект: `type` равен `authentication_error`, `code` равен `invalid_api_key`, `param` равен `null`. Если тело запроса превышает настроенный предел и отклоняется на этапе аутентификации, у этих путей `type` меняется на `invalid_request_error`, а `code` — на `request_body_too_large`. Если служба аутентификации возвращает 500 или выше, `type` равен `server_error`, а `code` — `authentication_service_error`. Обычные группы `/v1`, `/v1beta`, `/openai/v1` и `/backend-api/codex` по-прежнему используют строковый `error` выше.

Безопасный режим примерных ключей включается только при обычном запуске или TUI standalone. Он не включается для входа, импорта, `--siwc-bind`, Home и облачного развёртывания, когда файла конфигурации нет. Он также не включается, когда процесс только клиент TUI, подключённый к уже работающей службе. После включения, если в списке всё ещё есть `your-api-key-1`, `your-api-key-2` или `your-api-key-3`, префиксы `/v1`, `/v1beta`, `/openai/v1` и `/backend-api/codex` до входа в обработчик возвращают 403 и устанавливают заголовок ответа `X-CPA-SAFE-MODE: example-api-key`. Тело такое:

```json
{"error":"unsafe_example_api_key","message":"Proxy API endpoints are disabled because api-keys contains template values. Open /management.html?safe-mode=configure, update api-keys in Management, then retry."}
```

`GET` или `HEAD` `/` и `/management.html` тогда возвращают страницу предупреждения вместо прежнего ответа. Исключение — `/management.html?safe-mode=configure`. Он по-прежнему входит в панель управления.
