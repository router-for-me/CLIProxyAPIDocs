# Проверка работоспособности

## 1. Какую задачу решает этот раздел

Даёт проверку живучести, которая не идёт через маршрутизацию моделей, краткое описание на корневом пути и запрос keep-alive, который не даёт процессу, запущенному с локальным паролем, завершиться из-за отсутствия обращений.

## 2. Когда применимо и чего здесь нет

`GET /healthz`, `HEAD /healthz` и `GET /` не проверяют клиентский ключ API. Они не означают, что модель upstream пригодна, и не заменяют API управления. `GET /keep-alive` регистрируется только при запуске с локальным паролем.

## 3. Как настроить или вызвать

Замените хост на адрес, который реально слушает. В примере используется `https://example.invalid`.

`GET /healthz` возвращает `200` и `{"status":"ok"}`.

`HEAD /healthz` возвращает `200` без тела ответа.

`GET /` возвращает `200`. В JSON поле `message` равно `CLI Proxy API Server`, а список `endpoints` содержит `POST /v1/chat/completions`, `POST /v1/completions` и `GET /v1/models`.

`GET /keep-alive` регистрируется только при запуске с `--password`. Запрос должен нести этот локальный пароль в `Authorization: Bearer YOUR_API_KEY` или `X-Local-Password`. Успех возвращает `{"status":"ok"}`.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| GET /healthz | Возвращает JSON живучести. |  | Без ключа. `200`, тело `{"status":"ok"}`. |
| HEAD /healthz | Возвращает только код состояния живучести. |  | Без ключа. `200`, без тела. |
| GET /keep-alive | Сбрасывает таймер простоя процесса с локальным паролем. |  | Регистрируется только если при запуске был локальный пароль. 10 секунд простоя закрывают процесс. Несовпадение пароля — `401` с ошибкой `invalid password`. |
| GET / | Возвращает описание сервера и три примерные конечные точки. |  | Без ключа. Все маршруты не перечисляются. |

## 5. Типичные ошибки и границы

Без `--password` маршрут `GET /keep-alive` не появляется на сервере по умолчанию. Запрос попадает в незарегистрированный маршрут, а не в успешный keep-alive. Неверный пароль не сбрасывает таймер. Эти три публичные проверки не подтверждают, что учётные данные upstream всё ещё могут вызвать модель.

## 6. Связанные возможности

Порт прослушивания описан в разделе [Прослушивание и процесс](/ru/operations/server). Локальный пароль также используется для локального доступа к API управления. См. [Параметры управления](/ru/operations/management-settings).
