# TLS

## 1. Какую задачу решает этот раздел

Решает, слушает ли API-сервер по HTTPS и какие сертификат и закрытый ключ используются.

## 2. Когда применимо и чего здесь нет

Это действует только на прослушивание этого процесса. Здесь не настраивается клиентский mTLS плоскости управления Home и не заменяется TLS upstream `base-url`. Адрес и порт привязки описаны в разделе [Прослушивание и процесс](/ru/operations/server).

## 3. Как настроить или вызвать

```yaml
server:
  tls:
    enable: false
    cert: ""
    key: ""
```

При включении запишите в `cert` и `key` пути к файлу сертификата и файлу закрытого ключа. Не вставляйте закрытый ключ в пояснения к конфигурации или в журналы.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| server.tls.cert | Путь к файлу сертификата TLS. | empty string | Когда `enable` равен true, он не может быть пустым и должен вместе с закрытым ключом составлять пригодную пару сертификата. |
| server.tls.enable | Слушать ли по HTTPS. | false | При false сервер запускается как обычный HTTP. При true эта пара сертификата используется на привязанном адресе, и предпринимается попытка включить HTTP/2 и HTTP/1.1. |
| server.tls.key | Путь к файлу закрытого ключа TLS. | empty string | Когда `enable` равен true, он не может быть пустым. |

## 5. Типичные ошибки и границы

Если `enable` равен true, а путь сертификата или закрытого ключа пуст, запуск не удаётся с ошибкой `tls.cert or tls.key is empty`. Если пути заданы, но пару сертификата загрузить нельзя, запуск тоже не удаётся. Заполнить только один из путей недостаточно.
