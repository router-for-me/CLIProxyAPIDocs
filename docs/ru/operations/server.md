# Прослушивание и процесс

## 1. Какую задачу решает этот раздел

Здесь решается, на каком интерфейсе и порту слушает процесс, насколько велико может быть входящее тело запроса, доверять ли адресу клиента, переданному обратным прокси, и выключать ли дорогие журналы и промежуточные слои, чтобы снизить память при высокой параллельности. Токен для сведений о выпусках GitHub тоже здесь.

## 2. Когда применимо и чего здесь нет

Эти ключи принадлежат `server`. Они не выдают клиентский ключ доступа и не открывают API управления. Сертификаты HTTPS описаны в разделе [TLS](/ru/operations/tls). Объявления в локальной сети — в разделе [Обнаружение в локальной сети](/ru/operations/discovery). У режима Home своя нормализация порта. См. [CLIProxyAPI Home](/ru/operations/home).

## 3. Как настроить или вызвать

Пример конфигурации использует значения ниже. Незаписанные ключи всё равно следуют defaults из раздела 4.

```yaml
server:
  host: ""
  port: 8317
  max-request-body-bytes: 0
  github-token: ""
  trusted-proxies: []
  commercial-mode: false
```

Пример записи `trusted-proxies` — IP или CIDR, например `127.0.0.1` и `192.0.2.0/24`. Не записывайте токен в репозиторий. Если он нужен, используйте заполнитель `YOUR_API_KEY` либо оставьте пустым и перейдите на переменную окружения.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| server.commercial-mode | Чтобы снизить память на запрос, выключает дорогие журналы запросов и возможности HTTP-промежуточных слоёв. | false | При true для этого процесса не вешается промежуточный слой журнала запросов, а журналирование запросов на стороне SDK считается выключенным. |
| server.github-token | Глобальный токен запросов GitHub. Он важнее `GITHUB_TOKEN`. | empty string | Непустое значение конфигурации побеждает. Иначе по очереди используются `GITHUB_TOKEN` и `github_token`. `GITSTORE_GIT_TOKEN` используется только когда `GITSTORE_GIT_URL` указывает на github.com. Токен нужен только для HTTPS `api.github.com`. |
| server.host | Хост или интерфейс, к которому привязывается API-сервер. | Default is empty ("") to bind all interfaces (IPv4 + IPv6). | Пустая строка привязывает все интерфейсы IPv4 и IPv6. Чтобы ограничиться этой машиной, запишите `127.0.0.1` или `localhost`. |
| server.max-request-body-bytes | Предел тела входящего HTTP-запроса в байтах. | Values <= 0 disable the limit (default). | Меньше или равно 0 означает отсутствие предела. Запрос сверх предела возвращает HTTP 413. |
| server.port | Порт прослушивания API-сервера. | 0 | Обычная загрузка не меняет 0 на другой порт. В примере конфигурации записано 8317. Только порт, полученный из Home, меняется на 8317, если он опущен или неположителен. |
| server.trusted-proxies | IP или CIDR, которым разрешено передавать заголовок пересланного IP клиента. | nil | Пустой список не доверяет пересланным заголовкам. Применяется при запуске. Недопустимая запись (пусто, пробелы по краям, не IP и не CIDR) приводит к ошибке загрузки конфигурации. Если список нельзя применить, пересланные заголовки игнорируются. После изменения нужен перезапуск. |

## 5. Типичные ошибки и границы

Если `trusted-proxies` содержит пустую строку, пробелы по краям или неразбираемый адрес, загрузка конфигурации не удаётся. Ошибка говорит, что ожидается IP или CIDR. Если порт равен 0 и это не путь нормализации Home, процесс слушает `host:0` и сам не меняет его на примерный 8317. `commercial-mode: true` сам по себе не выключает API управления.
