# Терминальный интерфейс

## 1. Какую задачу решает этот раздел

Управлять уже работающим прокси из терминального интерфейса управления либо сначала поднять встроенный сервер в том же процессе и затем подключиться к нему.

## 2. Когда применимо и чего здесь нет

Сам `--tui` не выбирает учётную запись upstream. Без `--standalone` это только клиент API управления, и прокси уже должен работать. Ключ управления и `base-url` описаны в разделе [Параметры управления](/ru/operations/management-settings). Соединение Home — в разделе [CLIProxyAPI Home](/ru/operations/home).

## 3. Как настроить или вызвать

Только клиент:

```bash
cli-proxy-api --tui --management-base-url https://example.invalid
```

Встроить сервер в этот процесс и открыть терминальный интерфейс:

```bash
cli-proxy-api --tui --standalone
```

Соответствующий ключ конфигурации — `management.base-url`. Непустое значение командной строки важнее конфигурации. Если оба пусты, клиент подключается к `http://127.0.0.1:` плюс порт. Если `server.port` положителен, используется этот порт. Иначе используется 8317.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| --management-base-url | Базовый адрес удалённого API управления для клиентского режима TUI. | empty string | Выбирает цель только при `--tui` и без `--standalone`. Примерная форма — `https://example.invalid`. |
| --standalone | Запускает встроенный локальный сервер в режиме TUI. | false | Путь встроенного сервера используется только вместе с `--tui`. Если `--password` не задан, процесс создаёт локальный пароль управления, который существует только в памяти. Если встроенный сервер всё ещё не готов примерно после 30 проверок, процесс завершается и сообщает `embedded server is not ready`. |
| --tui | Запускает терминальный интерфейс управления. | false | При false процесс запускается как обычный прокси. |
| TUI | Пользовательский вход: запуск с терминальным интерфейсом управления. |  | Вход через `--tui`. Без `--standalone` этот процесс не запускает прокси. |

## 5. Типичные ошибки и границы

Один `--standalone` без `--tui` не открывает терминальный интерфейс и не встраивает сервер только из-за этого переключателя. Если клиентский режим не может достучаться до API управления, терминальный интерфейс сообщает `TUI error`. Встроенный режим временно направляет стандартный вывод и стандартный поток ошибок в пустое устройство, а при неудаче восстанавливает их и печатает ошибку. `--local-model` не печатает это замечание о запуске с локальным каталогом для чистого клиентского TUI (`--tui` без `--standalone`).

## 6. Связанные возможности

Базовый адрес и ключ описаны в разделе [Параметры управления](/ru/operations/management-settings). Конечная точка keep-alive появляется при заданном локальном пароле. См. [Проверка работоспособности](/ru/operations/health).
