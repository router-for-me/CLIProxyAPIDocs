# Параметры командной строки

Здесь описаны только параметры `CLIProxyAPI`, отнесённые к этой странице в закреплённом коммите. Имя двоичного файла совпадает с `./CLIProxyAPI` внутри образа. Разбор параметров Go принимает один или два дефиса. Ниже, как в заголовках реестра, записаны два дефиса.

## 1. Какую задачу решает этот раздел

Эти параметры выбирают, какой файл конфигурации читает процесс, нужно ли один раз выполнить обнаружение в локальной сети и выйти, открывать ли браузер при входе, какой локальный порт обратного вызова использовать, задавать ли локальный пароль управления и переходить ли на встроенный каталог моделей. Обнаружение записывается двумя способами: подкоманда `discover` и по-прежнему допустимые `--discover` / `--discover-json`.

## 2. Когда применимо и чего здесь нет

Это относится к прямому запуску двоичного файла. Подкоманда `discover` разбирается отдельно и завершается. Она не запускает прокси и не принимает старую группу `--discover-*`.

Здесь не описаны параметры входа провайдеров, настройка ключа управления и Docker Compose. `--vertex-import-prefix` действует только вместе с `--vertex-import`. Шаги импорта на этой странице не разбираются. `--password` не заменяет ключ управления: если и ключ управления, и переменная окружения `MANAGEMENT_PASSWORD` пусты, интерфейс управления этот пароль не принимает.

## 3. Как настроить или вызвать

Укажите файл конфигурации. Если значение пустое и нет источника конфигурации Postgres, объектного хранилища, Git или Home, загружается `config.yaml` из рабочего каталога.

```bash
CLIProxyAPI --config /path/to/config.yaml
```

Обнаружение подкомандой. `--include` и `--exclude` принимают имена сетевых интерфейсов через запятую. Имена не зависят от регистра, а `*` в конце означает префикс. Если хотя бы один из этих параметров непустой, оба списка фильтрации в файле конфигурации заменяются сразу.

```bash
CLIProxyAPI discover --timeout 3 --include eth0 --exclude "docker*"
CLIProxyAPI discover --json --config /path/to/config.yaml
```

Обнаружение старыми параметрами. Сам `--discover-json` начинает сканирование и затем завершает процесс.

```bash
CLIProxyAPI --discover --discover-timeout 3 --discover-include eth0 --discover-exclude "docker*"
CLIProxyAPI --discover-json
```

Встроенный каталог моделей, без автоматического открытия браузера, локальный пароль управления и запись Sign in with ChatGPT в уже существующий файл учётных данных Codex:

```bash
CLIProxyAPI --local-model
CLIProxyAPI --no-browser --siwc-bind credential.json
CLIProxyAPI --password YOUR_API_KEY
```

`credential.json` должен быть именем файла в настроенном каталоге аутентификации либо абсолютным путём к файлу внутри этого каталога. Если `--oauth-callback-port` больше 0, он перекрывает локальный порт обратного вызова для входа и для `--siwc-bind`. Значение по умолчанию `0` сохраняет собственный порт каждого провайдера.

```bash
CLIProxyAPI --vertex-import /path/to/service-account.json --vertex-import-prefix team-a
```

`team-a` — только пример префикса без косой черты. Это не значение по умолчанию.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно. Пустая ячейка означает, что поле — пустая строка.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| cli.server.config | Верхнеуровневый `--config`. Выбирает загружаемый YAML, если нет источника конфигурации Postgres, объектного хранилища, Git или Home. Если Home уже предоставил конфигурацию, непустое значение только сохраняется для последующих компонентов и не загружается повторно как файл конфигурации. | empty string | Пустое значение использует `config.yaml` в рабочем каталоге. |
| cli.server.discover | `--discover`. Ищет в локальной сети шлюзы ИИ и экземпляры CLIProxyAPI, печатает результат и завершается, не запуская прокси. | false | `--discover-json` входит в то же сканирование. |
| cli.server.discover-config | `--config` подкоманды `discover`. Нужен только чтобы прочитать `discovery.interfaces` из этого файла. | empty string | Это не верхнеуровневый `--config`. Если файл отсутствует или YAML недействителен, списки фильтрации пусты, а сканирование продолжается. Пустое значение использует `config.yaml` в рабочем каталоге. |
| cli.server.discover-exclude | Вместе с `--discover` или `--discover-json` пропускает перечисленные интерфейсы. |  | Через запятую; пустые и повторяющиеся элементы игнорируются. Если этот параметр или `--discover-include` непустой, оба списка командной строки заменяют фильтры в файле конфигурации. |
| cli.server.discover-include | Вместе с `--discover` или `--discover-json` сканирует только перечисленные интерфейсы и перекрывает отбор физических интерфейсов локальной сети по умолчанию. |  | Те же правила, что у `--discover-exclude`. |
| cli.server.discover-json | Выполняет то же сканирование, записывает шлюзы массивом JSON в стандартный вывод и завершается. | false | Не пишет баннер версии в стандартный вывод. |
| cli.server.discover-service-type | Вместе со старыми параметрами обнаружения задаёт тип службы DNS-SD. | empty string | Пустое значение использует `_ai-gateway._tcp`. |
| cli.server.discover-timeout | Вместе со старыми параметрами обнаружения задаёт тайм-аут сканирования в секундах. | 3 | Меньше или равно 0 считается как 3 секунды. Больше 60 секунд считается как 60 секунд. |
| cli.server.exclude | `--exclude` подкоманды `discover`: пропускает перечисленные интерфейсы. |  | Правила сопоставления те же, что у `--discover-exclude`. Если этот параметр или `--include` подкоманды непустой, они заменяют фильтры в файле конфигурации. |
| cli.server.include | `--include` подкоманды `discover`: сканирует только перечисленные интерфейсы и перекрывает отбор физических интерфейсов локальной сети по умолчанию. |  | Правила сопоставления те же, что у `--discover-include`. |
| cli.server.json | `--json` подкоманды `discover`. Выводит массив JSON и опускает баннер версии. | false | Ошибка сканирования становится объектом JSON с `error` и пустым `gateways`. |
| cli.server.local-model | Использует встроенный каталог моделей, когда соответствующий источник каталога пуст. Если `models.catalog`, `models.codex-catalog` или `models.devin-catalog` непусты, этот пункт по-прежнему берётся из явного источника. | false | Обычный запуск и TUI standalone его учитывают. Когда процесс только клиент TUI, подключённый к уже работающей службе, параметр не вызывается. |
| cli.server.no-browser | Вход OAuth не открывает браузер, а печатает адрес авторизации. | false | Вход Devin печатает адрес авторизации и предлагает вставить код авторизации или токен сеанса. В командную строку устанавливается интерактивная подсказка по умолчанию. |
| cli.server.oauth-callback-port | Если больше 0, перекрывает локальный порт обратного вызова для команд входа и `--siwc-bind`. | 0 | 0 сохраняет собственный порт провайдера. Devin без перекрытия использует временный порт. |
| cli.server.password | Локальный пароль управления, передаваемый службе. В тексте справки этот параметр не показан. | empty string | `GET /keep-alive` регистрируется только при обычном запуске и непустом параметре; 10 секунд простоя отсчитываются с момента включения конечной точки. TUI standalone не регистрирует эту конечную точку и не завершается из-за неё, даже если параметр непустой или пароль был создан, потому что параметр пуст. При обычном запуске с пустым параметром этот пароль не задаётся. TUI standalone создаёт пароль только когда параметр пуст. |
| cli.server.service-type | `--service-type` подкоманды `discover`. | empty string | Пустое значение использует `_ai-gateway._tcp`. |
| cli.server.siwc-bind | Указывает существующий файл учётных данных Codex, выполняет Sign in with ChatGPT, записывает раздел SIWC и `use_siwc=true`, затем завершается, не запуская прокси. | empty string | Допустимы только абсолютный путь или голое имя файла в каталоге аутентификации. На него действуют `--no-browser` и `--oauth-callback-port`. |
| cli.server.timeout | `--timeout` подкоманды `discover`, в секундах. | 3 | Меньше или равно 0 считается как 3 секунды. Больше 60 секунд считается как 60 секунд. |
| cli.server.vertex-import-prefix | Вместе с `--vertex-import` добавляет префикс к имени модели Vertex и к сохраняемому файлу учётных данных. | empty string | Если после удаления начальных и конечных косых черт остаётся `/`, сохранение отклоняется. Один только префикс ключ не импортирует. |

## 5. Типичные ошибки и границы

Если сканирование не нашло подходящий физический интерфейс, код выхода равен 1. Вывод не в JSON пишет в стандартный поток ошибок `Error scanning LAN: no qualified physical interfaces found for LAN discovery`. Вывод JSON — объект с `error` и пустым `gateways`. Отсутствие шлюзов ошибкой не является: код выхода 0, и печатается подсказка, включая требование `discovery.enabled: true` у цели. Конфигурация обнаружения здесь не разбирается.

Если подкоманда `discover` или разбор верхнего уровня встречает нераспознанный параметр, процесс завершается по `ExitOnError` Go с кодом выхода 2.

`--siwc-bind` отклоняет пустой путь, не настроенный каталог аутентификации, относительный путь с разделителем каталогов, отсутствующий файл и файл вне каталога аутентификации. Если порт обратного вызова уже занят, процесс завершается с ошибкой.

Если `--vertex-import-prefix` содержит косую черту, записывается ошибка `vertex-import: prefix must be a single segment (no '/' allowed)`, и учётные данные не сохраняются.

`GET /keep-alive` регистрируется только при обычном запуске и непустом `--password`. Конечная точка читает пароль из `Authorization: Bearer` или `X-Local-Password`. Отсутствие или несовпадение даёт 401 с телом `invalid password`. Отсчёт начинается с включения конечной точки: процесс завершается, если успешного вызова не было никогда или если с последнего успешного вызова прошло 10 секунд. TUI standalone не регистрирует эту конечную точку и не завершается из-за неё через 10 секунд, даже если пароль непустой или создан программой. Интерфейс управления по-прежнему сначала требует настроенный ключ управления или `MANAGEMENT_PASSWORD`. Если оба пусты, возвращается 403 `remote management key not set`, и этот параметр вместо них не используется. Локальный запрос, у которого такой ключ уже есть, может пройти проверку с этим параметром.

`--config` не может перекрыть уже включённый источник конфигурации Postgres, объектного хранилища, Git или Home.
