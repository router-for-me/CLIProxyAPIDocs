# Мышление моделей

## 1. Какую задачу решает этот раздел

Каждая группа ключей API upstream может объявить возможность мышления своих моделей: дискретные уровни или интервал бюджета токенов, а также можно ли выключить его нулём или передать -1 upstream для динамического распределения. Прокси проверяет и зажимает объём мышления, предложенный клиентом, по этому объявлению.

## 2. Когда применимо и чего здесь нет

Поля записываются в `api-keys.<провайдер>[].models[].thinking`. Провайдеры — claude, codex, gemini, interactions, meta, openai-compatibility, vertex и xai. Это описание возможности модели, а не бюджет одного запроса. Суффикс в скобках у имени модели здесь не описан. Встроенные возможности моделей в каталоге OAuth этими ключами по пунктам не перекрываются, если то же имя upstream не записано здесь в явный объект `thinking`.

## 3. Как настроить или вызвать

```yaml
api-keys:
  gemini:
    - name: gemini-1
      base-url: "https://example.invalid"
      keys:
        - api-key: "YOUR_API_KEY"
      models:
        - name: "gemini-2.5-flash"
          alias: "gemini-flash"
          thinking:
            levels: ["high", "medium", "low", "none", "auto"]
        - name: "gemini-2.5-pro"
          alias: "gemini-pro"
          thinking:
            min: 1024
            max: 32768
            zero-allowed: true
            dynamic-allowed: true
  openai-compatibility:
    - name: compatible
      base-url: "https://example.invalid"
      keys:
        - api-key: "YOUR_API_KEY"
      models:
        - name: "upstream-model"
          alias: "client-model"
          thinking:
            levels: ["low", "medium", "high"]
```

Модель с бюджетом заменяет `levels` на `min`, `max`, `zero-allowed` и `dynamic-allowed`. Не записывайте уровни и окно бюджета как одну и ту же действующую возможность. 1024 и 32768 в примере — только примеры. Это не значения по умолчанию этих ключей.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| api-keys.claude.models.thinking.dynamic-allowed | Разрешён ли бюджет -1, то есть динамический бюджет мышления. | false | Если levels содержит auto, нормализация ставит true. При false auto больше не остаётся -1: модель только с уровнями становится medium, а модель с диапазоном бюджета становится (min+max)/2. Явный объект thinking заменяет статические метаданные мышления на этом имени модели upstream. Если объект опущен, возможность из статического каталога всё ещё может сохраниться. |
| api-keys.claude.models.thinking.levels | Дискретные уровни рассуждения, которые разрешает эта модель. | nil | Если непусто, используются уровни, а не бюджет токенов. Значения обрезаются, переводятся в нижний регистр и дедуплицируются. Пустая строка отбрасывается. none одновременно включает zero-allowed, auto одновременно включает dynamic-allowed. Явный объект thinking заменяет статические метаданные мышления на этом имени модели upstream. Если объект опущен, возможность из статического каталога всё ещё может сохраниться. |

Если min или max не равен 0, включая случай когда оба не равны 0, бюджет того же семейства, который всё ещё пришёл из тела запроса и остаётся в режиме бюджета, возвращает BUDGET_OUT_OF_RANGE, если выходит за замкнутый интервал. Бюджет 0 сначала выходит из режима бюджета, поэтому эта ошибка не возвращается. Цель не Claude, которой нельзя 0, меняет его на min и пишет предупреждение. Если min всё ещё 0, результат всё ещё 0. Цель Claude при выключении мышления сохраняет бюджет 0. Явный объект thinking заменяет статические метаданные мышления на этом имени модели upstream. ## 5. Типичные ошибки и границы

Когда семейство провайдера то же, объём мышления пришёл из тела запроса, а не из суффикса имени модели, и `min` или `max` не равен 0 (оба ненулевые тоже считаются), бюджет, который всё ещё в режиме бюджета и вышел за замкнутый интервал, возвращает `BUDGET_OUT_OF_RANGE`. Бюджет 0 сначала становится выключенным мышлением, поэтому эта ошибка не возвращается. Цель не Claude затем обрабатывается clampBudget: если 0 нельзя, он становится min и пишется предупреждение. Если min всё ещё 0, результат всё ещё 0. Цель Claude при выключении мышления напрямую сохраняет бюджет 0. Если запрошенный уровень не входит в `levels` и его нельзя зажать до поддерживаемого уровня, возвращается `LEVEL_NOT_SUPPORTED`. Одновременные 0 у `min` и `max` из-за этого не отклоняются. Просто числовое окно не строится. `dynamic-allowed: false` не отклоняет auto. Он меняет его на medium или на середину бюджета.
