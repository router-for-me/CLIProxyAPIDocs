# Три: практика NanoBanana

Цель — выполнить одну генерацию изображения или Gemini через этот прокси, используя модель изображений, уже зарегистрированную в каталоге. Эта страница не добавляет имён моделей и не собирает cookie.

## Сценарий

Вы хотите, чтобы клиент вызывал возможности изображений через CLIProxyAPI. В текущей программе нет параметра входа Gemini Web по cookie. Не выполняйте несуществующую команду входа и не вставляйте cookie браузера в конфигурацию.

## Шаги

1. В разделе [Каталоги моделей](/ru/introduction/models) подтвердите, что вызываемый ID взят из текущего каталога. Эта страница не определяет NanoBanana как фиксированный ID.
2. Подготовьте ключ для клиента. См. [Клиентские ключи](/ru/api/access). В запросе используйте `YOUR_API_KEY`.
3. Для генерации или редактирования изображений в совместимом с OpenAI виде вызывайте только маршруты и разрешённые имена моделей из раздела [Изображения, речь и видео](/ru/api/media).
4. Для Gemini `generateContent` вызывайте только путь из раздела [Gemini](/ru/api/gemini). Хост в примере — `https://example.invalid`. Не пишите на этой странице другую таблицу конечных точек.
5. Если upstream — ключ Gemini API, ключ описан в разделе [Ключи upstream API](/ru/accounts/api-keys-api), адрес — в разделе [Базовые URL upstream](/ru/accounts/api-keys-base). Псевдонимы — в разделе [Псевдонимы моделей upstream](/ru/accounts/api-keys-models).
6. Если модели нужен уровень мышления, меняйте только раздел [Мышление моделей](/ru/configuration/thinking-models).
7. Если у одной модели несколько учётных данных, порядок выбора описан в разделе [Стратегия маршрутизации](/ru/routing/strategy). Временный пропуск после сбоя — в разделе [Охлаждение](/ru/routing/cooldown).

## Чего не следует завершать на этой странице

Не сохраняйте здесь cookie браузера, не описывайте шаги интерфейса стороннего клиента и не повторяйте поля тела запроса маршрутов изображений.
