# Облачное развёртывание (хранилище Git)

Если диск контейнера ненадёжен, храните конфигурацию и токены в репозитории Git, затем вызывайте прокси обычным способом.

## Сценарий

Удалённый адрес Git и аутентификация открываются переменными окружения. У удалённого хранилища нет покрытой функциональной страницы. Эта страница не перечисляет имена переменных, обязательность или порядок запуска и не считает непокрытую старую страницу списком.

## Шаги

1. Не записывайте персональный токен доступа в учебник или репозиторий. Готовя переменные, не используйте эту страницу или непокрытую старую страницу хранилища как список.
2. При вызове GitHub API то, что важнее — токен в конфигурации или `GITSTORE_GIT_TOKEN`, — определяется только описанием `server.github-token` в разделе [Прослушивание и процесс](/ru/operations/server). Не переписывайте этот приоритет здесь.
3. Процесс по-прежнему запускайте разделом [Запуск через Docker Compose](/ru/docker/docker). Там сказано, что ожидание облачного развёртывания начинается только когда `DEPLOY` равен `cloud`. Больше ожидание здесь не объясняется.
4. Правила доступа для пароля управления следуют разделу [Параметры управления](/ru/operations/management-settings).
5. Содержимое конфигурации в репозитории — по-прежнему обычная конфигурация. Клиентский ключ — в разделе [Клиентские ключи](/ru/api/access), ключ upstream — в разделе [Ключи upstream API](/ru/accounts/api-keys-api), каталог учётных данных — в разделе [Каталог OAuth, псевдонимы и исключения](/ru/accounts/oauth).
6. Прослушивание процесса описано в разделе [Прослушивание и процесс](/ru/operations/server). После запуска используйте [Проверка работоспособности](/ru/operations/health).

## Чего не следует завершать на этой странице

Не описывайте последовательность щелчков создания репозитория на Git-хостинге и не приводите настоящие адрес репозитория или токен.
