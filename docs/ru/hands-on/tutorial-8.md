# Облачное развёртывание (хранилище в базе данных)

Если диск контейнера ненадёжен, храните конфигурацию и токены в PostgreSQL, затем вызывайте прокси обычным способом.

## Сценарий

Соединение с базой открывается переменными окружения. У удалённого хранилища нет покрытой функциональной страницы. Эта страница не перечисляет имена переменных, обязательность или порядок запуска и не считает непокрытую старую страницу списком.

## Шаги

1. Не записывайте пароль из строки соединения в учебник или репозиторий. Готовя переменные, не используйте эту страницу или непокрытую старую страницу хранилища как список.
2. Процесс по-прежнему запускайте разделом [Запуск через Docker Compose](/ru/docker/docker). Там сказано, что ожидание облачного развёртывания начинается только когда `DEPLOY` равен `cloud`. Больше ожидание здесь не объясняется.
3. Правила доступа для пароля управления следуют разделу [Параметры управления](/ru/operations/management-settings).
4. Содержимое конфигурации в базе — по-прежнему обычная конфигурация. Клиентский ключ — в разделе [Клиентские ключи](/ru/api/access), ключ upstream — в разделе [Ключи upstream API](/ru/accounts/api-keys-api), каталог учётных данных — в разделе [Каталог OAuth, псевдонимы и исключения](/ru/accounts/oauth).
5. Прослушивание процесса описано в разделе [Прослушивание и процесс](/ru/operations/server). После запуска используйте [Проверка работоспособности](/ru/operations/health).

## Чего не следует завершать на этой странице

Не описывайте последовательность щелчков размещённой платформы и не приводите настоящую строку соединения с базой.
