# Пять: развёртывание сервера в Docker

На машине, где Docker Compose уже установлен, запустите службу файлом Compose из репозитория и выполните одну проверку живучести, которая не проходит через модель.

## Сценарий

Машина может быть VPS или другим хостом. Установка самого Docker не является возможностью этого продукта. Скрипт установки здесь не приводится.

## Шаги

1. Запускайте и останавливайте из корня репозитория, где лежит `docker-compose.yml`, по разделу [Запуск через Docker Compose](/ru/docker/docker). Не пишите на этой странице другое определение сервиса или таблицу портов.
2. Порты, публикуемые контейнером, а также хост и порт, к которым реально привязывается процесс, определяются той страницей и разделом [Прослушивание и процесс](/ru/operations/server). Если они расходятся, не усредняйте их в учебнике.
3. В конфигурации, смонтированной в контейнер, клиентский ключ меняйте только по разделу [Клиентские ключи](/ru/api/access). Конечную точку управления — только по разделу [Параметры управления](/ru/operations/management-settings). Каталог учётных данных — только по разделу [Каталог OAuth, псевдонимы и исключения](/ru/accounts/oauth).
4. После запуска процесса откройте проверку работоспособности. См. [Проверка работоспособности](/ru/operations/health). Это не доказывает, что модель upstream пригодна.
5. Журналы или использование — в разделе [Журналы и использование](/ru/operations/observability). Переход на HTTPS — в разделе [TLS](/ru/operations/tls).
6. Если диск будет потерян или нужны база данных, объектное хранилище или Git, покиньте эту страницу и следуйте соответствующему учебнику облачного развёртывания. Те учебники тоже только ссылаются на страницы хранилища и не копируют таблицу переменных окружения.

## Чего не следует завершать на этой странице

Не пишите команду клонирования, не копируйте полный текст `config.example.yaml` и не пишите правила брандмауэра.
