# Проксирование запроса

## 1. Какую задачу решает этот раздел

Вызывающий, уже прошедший аутентификацию ключом управления, поручает процессу отправить один HTTP-запрос на другой адрес и при необходимости использовать токен и прокси одной учётной записи.

## 2. Когда применимо и чего здесь нет

Есть только `POST /v8/management/requests/api-call`. Нужен ключ управления. Правила описаны в разделе [Management API v8](/ru/management/apiv8). Это не публичный маршрут модели, и учётные данные за вызывающего не сохраняются.

## 3. Как настроить или вызвать

```http
POST /v8/management/requests/api-call HTTP/1.1
Host: example.invalid
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "method": "GET",
  "url": "https://example.invalid/v1/models",
  "header": {},
  "data": ""
}
```

Необязательные поля:

- `auth_index`, `authIndex` или `AuthIndex`: индекс в списке учётных данных. Если опущено, отдельный прокси учётной записи не выбирается.
- `proxy_url`: прокси только для этого запроса. Он должен разбираться как прокси.
- `header`: заголовки запроса в виде строк.
- `data`: исходное тело запроса строкой. Пустая строка означает отсутствие тела.

Литерал `$TOKEN$` в заголовке или в `data` заменяется токеном этой учётной записи. При успехе интерфейс возвращает 200. Тело содержит upstream `status_code`, `header` и `body`. Статус upstream не 2xx не становится статусом ошибки этого интерфейса управления.

## 4. Подробности

Столбец «По умолчанию» совпадает с `defaults` в реестре дословно.

| Поле | Значение | По умолчанию | Ограничение |
| --- | --- | --- | --- |
| POST /v8/management/requests/api-call | Отправляет один HTTP-запрос с заданными методом и URL. |  | `method` и `url` обязательны. У URL должны быть схема и хост. Тайм-аут — 60 секунд. Если `$TOKEN$` нельзя разрешить, ответ — 400. Сетевой сбой или ошибка чтения ответа — 502. |

## 5. Типичные ошибки и границы

Тело не в JSON — 400 `invalid body`. Нет метода — 400 `missing method`. Нет URL — 400 `missing url`. У URL нет схемы или хоста — 400 `invalid url`. `proxy_url` не разбирается — 400 `invalid proxy_url`. Если задан `auth_index`, учётные данные не найдены и при этом нужно заменить `$TOKEN$`, ошибка 400 — `auth credential not found for auth_index`. Если токена нет, ошибка — `auth token not found`. Если обновление не удалось, ошибка — `auth token refresh failed`. Заголовок с именем `Host` меняет Host запроса, а не является обычным заголовком.
